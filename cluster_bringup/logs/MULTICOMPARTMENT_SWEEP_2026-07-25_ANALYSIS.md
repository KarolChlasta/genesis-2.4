# Multicompartment GPU-tree-elimination speed sweep — 2026-07-25, inf02/A40 + inf03/A100

Karol Chlasta. Raw data: `multicompartment_sweep_inf02_A40_20260725_150303.csv`,
`multicompartment_sweep_inf03_A100_20260725_150506.csv`. Generated by
`50_multicompartment_sweep.sh`, run in parallel on both nodes via the
shared cluster home. This is the first systematic (not spot-check) N x
NCOMP sweep of the validated `hines_tree_eliminate` GPU multiloop kernel
against the CPU reference — see `genesis/src/hines/GPU_HINES_SOLVE_DESIGN.md`
for the full correctness-validation history this builds on.

Model: `hh_multicompartment_benchmark.g` (N independent linear-chain
neurons x NCOMP compartments each, real AXIAL/RAXIAL coupling, HH Na+K on
every compartment). CPU = chanmode 1 (real CPU Hines reference). GPU = GPU
tree-elimination multiloop (chanmode 4 + `GENESIS_CUDA_MULTILOOP`/
`GENESIS_OCL_MULTILOOP`, `GENESIS_OCL_TREE_MAX_NCOMPTS=0` to disable the
iGPU-specific safety cap -- not needed on real cluster hardware, see the
design doc). Timing via the `walltimemark`/`{walltime}` `CLOCK_MONOTONIC`
timer, excluding SLI model-construction time.

## Reading the numbers

1. **Both GPUs show the same qualitative shape**: a fixed per-dispatch
   overhead (2 kernel launches/step, no per-step host round trip within a
   batch, but still real launch + tiny-transfer latency) dominates at small
   problem sizes, where GPU is *slower* than CPU. Past a crossover -- around
   N~300-500 (NCOMP=16) or NCOMP~6-8 (N=1000) on the A40, and a bit *earlier*
   on the A100 -- GPU throughput wins increasingly with problem size, since
   the CPU cost scales with total compartments (O(N x NCOMP)) while the
   fixed overhead does not.
2. **A100 beats A40 at every matched point past the earliest, smallest
   sizes**, and the gap widens with problem size: 1.46x -> 3.19x at
   N=1000/NCOMP=16 (A100 ~2.2x the A40's speedup), growing to 12.7x -> 29.1x
   at N=10000 (A100 ~2.3x the A40's speedup). Consistent with the A100
   having more SMs (108 vs 84) and higher memory bandwidth that only pays
   off once there's enough parallel work to use them -- exactly the
   multi-gen GPU comparison story flagged as valuable for the paper.
3. **A100's crossover point is earlier**: at NCOMP=4 (N=1000, smallest
   tested), the A100 is already 1.17x faster while the A40 is still 1.85x
   *slower* -- the A100's per-dispatch overhead is apparently lower in
   absolute terms too, not just its peak throughput higher.
4. **Best measured speedup this sweep: 29.1x on A100 at N=10000, NCOMP=16**
   (160000 total compartments) -- the largest total-compartment point
   tested. Both N and NCOMP scaling show the same monotonically-increasing-
   speedup-with-size pattern, so larger models (not yet tested -- see next
   steps) would very plausibly show even better numbers, until some other
   limit (device memory, kernel occupancy saturation) is reached.

## Not yet done

- This sweep's N x NCOMP grid is a reasonable first cut, not exhaustive --
  a finer grid (especially resolving the exact crossover points, and
  testing well past N=10000/NCOMP=64) would sharpen the paper's numbers.
- inf04 (4x A40) and inf05 (H200) not tried at all.
- Branching topologies not included in this speed sweep (only linear
  chains) -- correctness was separately validated on branching models
  (see the design doc) but their relative GPU speedup profile (more
  COPY_ARRAY/opcode-divergence between work-items for irregular trees)
  has not been measured.
- No power/energy measurements (relevant for a "why GPU" argument beyond
  raw wall-clock speedup).
